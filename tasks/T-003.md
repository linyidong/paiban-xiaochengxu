# T-003 软删除成员并保留排班

- 任务编号：T-003
- 阶段：7
- 优先级：P0
- 风险等级：高（数据语义）
- 对应需求：F-007
- 前置任务：无
- 状态：进行中

## 1. 目标

删除成员改为软删除：`users.isDeleted=true` + `deletedAt`，不再删除 `users`/`shifts`；所有成员相关查询过滤已删除；前端文案与实现一致。

## 2. 修改范围

**允许修改：**
- `cloudfunctions/manageMember/index.js`（list/bindWechat/createAndBind/add/remove/unbind/checkAdmin）
- `cloudfunctions/getShifts/index.js`
- `cloudfunctions/login/index.js`
- `cloudfunctions/importShift/index.js`
- `cloudfunctions/updateShift/index.js`
- `miniprogram/pages/calendar/calendar.js`、`miniprogram/pages/members/members.js`（仅删除提示文案）
- `tests/helpers/mock-cloud.js`、新增 `tests/t003-soft-delete.test.js`

**明确禁止：**
- 不物理删除 `users`/`shifts`（本任务移除该行为）
- 不改集合名、不改 `shifts` 结构
- 不改前端交互结构（仅文案）
- 不迁移/批量改写线上数据（旧数据无 `isDeleted` 视为未删除）

## 3. 验收标准（可数）

- [ ] 删除后 `users` 文档仍在且 `isDeleted=true`，`deletedAt` 存在
- [ ] 删除后该成员 `shifts` 行数不变（0 删除）
- [ ] `manageMember.list` 不返回已删除成员
- [ ] `getShifts` 的 `members` 与 `shiftsMap` 均不含已删除成员及其排班
- [ ] `updateShift` 目标为已删除成员 → `ok:false`
- [ ] `bindWechat`/`createAndBind`/`add` 对已删除同名成员返回明确错误，不静默复用
- [ ] 旧数据（无 `isDeleted` 字段）仍正常显示/可改
- [ ] 删除确认文案：成员隐藏、排班保留

## 4. 测试要求

- `node --test tests/t003-soft-delete.test.js` 全部通过
