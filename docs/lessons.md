# 经验教训（L3）

> 跨阶段、跨会话复用的经验。每条写清：现象 → 根因 → 做法。
> 项目级事实进 `docs/progress.md`；决策进 `docs/decisions.md`，不要混。

## 2026-10-25

### L-001 Windows PowerShell 读 UTF-8 中文会“假报错”

- 现象：用 `Get-Content` 读《人工必填参数清单.json》后，按中文键名写的正则匹配不到 `AI识别API_KEY`，一度误判“密钥已从工作区移除”。
- 根因：Windows PowerShell 5.1 默认按 ANSI 解码无 BOM 的 UTF-8 文件，中文变 mojibake；用 Node/正则按中文键名自然失配。
- 做法：判断文件内容一律用 `[System.IO.File]::ReadAllText($p, UTF8)` 或 Node 读取；控制台显示的乱码不能作为“文件损坏/字段缺失”的证据。写文件用 `.NET UTF8Encoding($false)`，避免 BOM。

### L-002 审计先跑“机器可判定”的检查，再读业务逻辑

- 现象：人工通读容易漏掉“事件处理器不存在”“require 路径写错”这类硬错误。
- 做法：先用脚本做 JSON 解析、WXML 事件与 JS 方法对账、require 解析、云函数调用关系；0 问题后再进入业务阅读。本轮 22/22 JSON、0 缺失处理器、0 缺失 require，节省了大量人工核对。

### L-003 文案与实现必须逐条对照

- 现象：日历页删除成员写“历史排班将保留”，后端实际级联删除；导入弹窗写“覆盖当月”，实现只 upsert。
- 做法：每个“承诺型文案”（覆盖/保留/删除/同步）都去代码里找对应行为；找不到就列为 defect，而不是当文案小事。

### L-004 视觉问题用测量代替目测

- 现象：“看起来还行”的界面，实测白字 on `#F3F4F6` 只有 1.10:1，正文 12–14px。
- 做法：写 WCAG 对比度脚本 + 统计字号/颜色字面量，把“可读性”变成可数判据；黑白模式截图还能验证“是否只靠颜色传达信息”。

### L-005 覆盖类功能必须自带“止损三件套”

- 现象：导入设计为“覆盖当月”，但识别可能错列/少行，一旦直接覆盖会整月误删。
- 做法：预览差异（新增/覆盖/清空数量）+ 清空 >0 二次确认 + 覆盖前导出目标月份备份；三者缺一不可。

### L-006 小程序项目没有现成测试环境

- 现象：只有生产云环境，写入型验收会污染真实排班。
- 做法：测试用“专用测试成员 + 空月份（如 2024-01）”，测试后软删除；禁止在真实成员真实月份做覆盖测试，除非用户授权并已导出备份。
