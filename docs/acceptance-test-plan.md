# 验收与测试计划

> 阶段 6 建立，阶段 7–8 补全结果。结果只允许四态：**通过 / 失败 / 未执行 / 未覆盖**。
> 没有运行的测试，不要写成“通过”。

## 1. 测试层次

- 单元测试：纯函数（日期校验、覆盖差异、权限判定、姓名归并、年份分组、Excel 解析）。
- 集成测试：云函数 + 云数据库（用专用测试成员与空月份）。
- 端到端：开发者工具/真机走完整流程（登录→导入→改班→备忘录→删除）。
- 手工验收：视觉（截图/对比度）、异常路径、权限边界。

## 2. 测试范围

| 范围 | 是否覆盖 | 说明 |
|---|---|---|
| 核心业务流程 | 是 | 登录绑定、导入、改班/取消、软删除、备忘录 |
| 认证/权限 | 是 | 3 类写接口 × 成员/管理员 |
| 数据读写与覆盖 | 是 | 导入全量替换、日期合法性、软删除过滤 |
| 外部接口 | 部分 | AI 识别用真实截图；失败路径用错误配置/断网模拟 |
| 异常与边界 | 是 | 空表、错表头、超时、重复提交、越权、跨年 |

## 3. 环境与数据

- 测试环境：微信开发者工具模拟器 + 云开发环境（当前只有生产环境）。
- 测试数据：
  - **专用测试成员**（如「测试-甲」「测试-乙」），测试结束软删除；
  - **空月份**（建议 `2024-01` 等历史空月）避免污染真实排班；
  - 真实截图与 xlsx 样例放 `tests/fixtures/`（不含真实姓名可脱敏）。
- 外部服务 mock：AI 识别不可 mock 时，用“错误端点”验证失败路径；成功路径用 1 张真实截图。
- 数据库重置：测试成员 + 空月份删除记录即可；生产数据不做重置。
- **红线**：不得在真实成员的真实月份上执行“全量覆盖”测试，除非用户明确授权并已导出备份。

## 5. 必须考虑的失败场景

- 无效输入：空姓名、超长文本（>500）、非法日期、非图片文件、>10MB。
- 外部服务：AI 超时（60s）、429/5xx、网络断开、云函数超时。
- 权限：成员改他人、成员导入他人、非管理员调 `manageMember.add/remove`、伪造 session.role。
- 重复/并发：连续点确认、同人同天并发写、重复导入。
- 数据：空月份、软删除后同名、旧数据无 `year/isDeleted` 字段。
- 视觉：小屏 320 宽、字体放大、深浅背景。
