# AI 生成代码审查清单

> 来源：本项目**实际审出的 25 个缺陷**（见 `docs/known-issues.md`）归纳出的检查项。
> 用法：AI 写完一个模块 → 按下面顺序扫一遍 → 逐项落"通过 / 不适用 / 已开缺陷号"。
> 一句话：**AI 不会写错语法，它错在"想当然"——所以清单针对的是它的系统性偏差，不是语法。**

---

## 一、为什么需要清单，而不是"看一遍"

AI 生成代码的偏差是**系统性的**，每次都在同几个地方栽：

| AI 的默认倾向 | 后果 | 本项目实例 |
|---|---|---|
| 只校验"登录了"，不校验"是不是你的" | 任意成员改他人数据 | BUG-001、BUG-002 |
| 把"覆盖"实现成"upsert" | 旧数据残留，看起来成功实际错了 | BUG-005 |
| 用 `new Date()` 取当前年月 | 跨月/跨年导入全错 | BUG-006、BUG-008 |
| 配置缺失时返回 mock 假数据"让流程能跑通" | 上生产后污染真数据 | BUG-020 |
| 用 `name` 当关联键 | 重名/改名导致数据错位 | RISK-009 |
| 加 `limit()` 防止慢查询，但不告诉调用方被截断 | 静默丢数据 | BUG-019 |
| 声明了配置常量却不用，另写一份硬编码 | 双源不一致 | BUG-013、DEBT-002 |
| CSS 只写"看起来对"的样式，不看选择器权重 | 在某些状态不可读 | BUG-012 |

**所以审查不是通读，是按偏差清单定点扫。**

## 二、第一层：三处必查（不通过就不算交付）

这三处 AI 错得最多，且错了后果最重。

### 2.1 数据模型

- [ ] 每个"写"操作，落在哪个集合/表？字段类型是否统一（同一个字段不能既是 ID 又是 name）
  > 反例：BUG-023 `shifts.updatedBy` 一处写 `users._id`、一处写 `OPENID` → 审计字段作废
- [ ] 关联用的是**主键**还是**业务字段**？用 name / 昵称关联的一律打回
  > 反例：RISK-009 `getShifts` 用 `userId→name` 映射，改班按 `users.name` 定位 → 重名就串
- [ ] 有没有"同一条记录应该唯一"的地方却没约束？
  > 反例：RISK-008 `shifts` 无 `(userId, date)` 唯一索引，两个入口都是"先查再写"非原子 → 可能重复
- [ ] 软删除的字段真的被所有查询尊重了吗？软删后敏感字段清了吗？
  > 反例：RISK-010 软删只置 `isDeleted`，`openid` 没清 → 同一个人能再绑定

**搜什么**：`.add(`、`.update(`、`.remove(`、`where(`、`_id`、`openid`、`isDeleted`、`limit(`

### 2.2 权限判断

- [ ] 每个云函数/接口入口，除了"登录态"，是否校验了**操作对象的归属**？
  > 反例：BUG-001 注释原话"所有登录用户均可修改排班…后端仅校验登录态"
- [ ] "管理员"判定读的是**白名单**还是**数据库里的 role**？后者可被改库提权
  > 反例：RISK-004 角色可被库内 `role` 放大
- [ ] 返回给前端的字段有没有过度暴露？（openid、内部 ID、他人手机号）
  > 反例：BUG-017 `list` 向所有人返回全量 openid
- [ ] 前端隐藏的按钮，后端是否也拦了？（前端限制不算限制）
  > 反例：Q-002 前端允许选人、后端不校验

**搜什么**：`getWXContext`、`OPENID`、`role`、`isAdmin`、`ADMIN_OPENIDS`、`return {`（看返回体）

### 2.3 异常处理

- [ ] 配置缺失时，是**报错**还是**返回假数据**？
  > 反例：BUG-020 未配置 Key → 返回 mock 排班并提示"识别成功" → 生产数据污染。正确做法：`isVisionConfigured()` 返回 false 就失败
- [ ] 每个 `await` 都有失败分支吗？超时呢？
  > 反例：RISK-003 云函数默认超时 3s，识别要 10–36s → 必须显式配置 60s
- [ ] 写到一半失败，数据会不会半截？
- [ ] 用户看到的是人话还是 `err.message`？

**搜什么**：`try`、`catch`、`throw`、`mock`、`MOCK`、`return { success: true`（假成功高发点）

## 三、第二层：12 类高频缺陷（按本项目命中次数排序）

| # | 缺陷类型 | 搜什么 | 判据 | 本项目实例 |
|---|---|---|---|---|
| 1 | **越权写** | `getWXContext` 后是否有 owner 校验 | 换一个普通用户身份，能否改到别人的数据 | BUG-001、002 |
| 2 | **"覆盖"写成 upsert** | `.update(` 旁边有没有 `.remove(` | 导入一份只含 1–5 号的表，6–31 号旧数据必须消失 | BUG-005 |
| 3 | **时间硬编码** | `new Date()`、`getFullYear`、`getMonth` | 换一个月/换一年导入，日期是否跟着变 | BUG-006 |
| 4 | **跨期匹配只比对月** | 日期比较、`slice(0,7)` | 加"年"维度后，次年同月不应命中 | BUG-008 |
| 5 | **静默截断** | `.limit(`、`.skip(` | 数据量翻倍时，是否有"还有更多"的提示或分页 | BUG-019 |
| 6 | **mock 兜底** | `mock`、`placeholder`、`|| {}` 默认值 | 依赖不可用时，必须失败而不是给假数据 | BUG-020 |
| 7 | **非法日期** | `31`、`28`、`补足` | 2 月不能出现 31 号；入库前 `isValidDate` | RISK-002 |
| 8 | **双源配置** | `DEFAULT_`、硬编码数组 | 同一个枚举只能在 `config.js` 一处定义 | BUG-013、DEBT-002 |
| 9 | **声明未用/死代码** | import 了但没用的常量 | `SHIFT_TYPES` 引入全文未使用 → 说明有两套语义在打架 | BUG-013 |
| 10 | **文案与实现矛盾** | "将保留"、"将删除"、提示语 | 弹窗说的和后端做的必须一致 | BUG-009 |
| 11 | **边界可点** | 补位格、禁用态、`bindtap` | 灰色/禁用元素不该触发写操作 | BUG-010 |
| 12 | **可读性/对比度** | 同权重选择器、`rpx`、字号 | 白字 + 浅灰底同权重会被后者覆盖；正文小于 16px 不合格 | BUG-012、021、022、024 |

## 四、第三层：验收门禁（"能数"才算过）

AI 说"已完成"不算完成。每个任务必须有**可数判据**，写进任务号（T-xxx）：

| 门禁 | 可数判据示例 |
|---|---|
| 缺陷闭环 | 每个缺陷一个任务号，修复必须有"复现步骤 → 修复后现象" |
| 测试 | 新增/修改逻辑必须有测试；本项目基线 **21 个测试文件** |
| 越权 | 至少一条"普通用户改他人数据"的用例，必须失败 |
| 幂等 | 同一操作执行两次，结果数据只能有一份 |
| 边界 | 闰年 2 月、跨年、空数据、超量数据各一条 |
| 文档 | 数据模型 / 接口契约 / ADR 各更新一次 |

> 反面教材：本项目起步时 **0 个自动化测试**（DEBT-004）。补测试不是为了好看，是因为没有测试就没法证明"修好了还没修坏"。

## 五、怎么给 AI 写返工要求（模板）

不合格时**不要只说"改一下"**，按这个结构写，AI 一次就能改对：

```
缺陷号：BUG-00X
现象：（一句话，可复现）
复现：1) … 2) … 3) …
期望：（可数判据，例如"6–31 号旧班次必须被清空"）
原因：（我定位到的文件:行，例如 importShift/index.js:100-113 只有 upsert 没有 remove）
不要动：其它已通过的逻辑；不要用 mock 绕过
验收：我会用 XXX 步骤复跑一遍
```

**关键三句**：给文件行号、给可数期望、明确"不要动什么"。少了任何一句，AI 都会顺手改坏别的地方。

## 六、一页速查（打印贴屏幕边）

```
□ 每个写操作：谁 → 改谁的数据 → 校验归属了吗
□ 每个返回体：有没有多给 openid / 内部 ID
□ 每个"覆盖"：有没有 delete
□ 每个日期：年从哪来，跨年怎么办，2 月 31 日挡住没
□ 每个 limit：被截断了会说话吗
□ 每个外部依赖：挂了是报错还是给假数据
□ 每个枚举：是不是第二份定义
□ 每个提示文案：和后端行为一致吗
□ 每个灰色/禁用元素：会不会被点到
□ 每个新逻辑：有几条测试，测试能证明什么
```

---

> 维护：每审出一个新类型的缺陷，就往第三节加一行。清单的价值在"每次都用"，不在"写得多"。
